- (decision) Use a TypeScript modular monolith with Next.js App Router: route handlers/server actions are transport only and call feature use-cases; features may depend only on shared contracts and infrastructure ports, never on another feature's persistence.
- (decision) The server owns authorization, validation, scoring, publication, and evidence aggregation. Browser code owns only rendering, media preload/playback, and recoverable in-progress drafts.
- (decision) A published practice set materializes immutable question, answer-policy, feedback, tag, and media-version snapshots. Attempt scoring uses the snapshot referenced by its attempt and never current editable content.
- (decision) Only submit-attempt invokes deterministic scoring. It atomically persists item responses, scoring outcomes, playback events, and evidence projections; the endpoint uses an idempotency key and rejects any second finalization.
- (decision) Use PostgreSQL as the system of record, S3-compatible private object storage for media, and IndexedDB only for local draft recovery. The service worker caches app shell and set assets after authorization; it must not cache answer or result payloads.
- (decision) Authentication is local credential login for admin-created accounts using Argon2id password hashes and opaque server-side sessions in Secure HttpOnly SameSite=Lax cookies. Role and resource authorization is enforced in every server use-case.
- (decision) Account deletion is a server-side transaction that revokes sessions, removes learner diagnostic/attempt data and media references per product policy, then creates an audit record containing no student response content.
- (assumption) Deployment remains provider-neutral for P0: one HTTPS Node.js application, managed PostgreSQL, and private S3-compatible object storage. Select a provider before production deployment.
- (decision) Published practice sets require approved question/media versions and immutable provenance: origin, creator/source reference, applicable rights/license reference, and generation metadata where applicable.
- (event) spine finalized
- (decision) P0 account removal is soft deactivation: set deactivation metadata, revoke sessions, deny future authentication/authorization, and retain practice/diagnostic records; irreversible purge is deferred.
