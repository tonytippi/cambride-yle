## Findings

### Verification gap: revoked learner session is not exercised after deactivation

- **Source:** `tests/e2e/teacher-evidence.spec.ts:118-146` verifies the learner account status and the `sessions.revoked_at` database field after deactivation, but does not reuse `fixture.learnerSessionToken` against a protected learner route. The actual session lookup rejects both revoked sessions and inactive accounts in `src/features/identity/infrastructure/repositories.ts:15-18`.
- **Trigger:** A regression in session lookup, session revocation filtering or protected-route enforcement after an admin deactivates the learner.
- **Consequence:** The current Epic 5 E2E path could still pass while a browser holding the already-issued learner cookie continues into a protected learner/practice route.
- **Disposition:** Defer as tracked verification work. The real repository predicate and database revocation assertion support the delivered behaviour, but the end-to-end boundary is not demonstrated.
- **Prevention lesson:** A lifecycle E2E that revokes an existing credential should replay that credential against one protected route rather than asserting persistence fields alone.

### Verification gap: no composed provision-to-first-attempt journey

- **Source:** Story 5.1 requires creation of an ordinary learner account followed by sign-in, published-set selection, preparation and server-authoritative attempt start (`spec-5-1-set-up-a-supervised-first-practice-session.md:64-68`). The added coverage separately tests role checks with a mocked learner actor in `tests/unit/practice-application.test.ts:63-83` and admin redirection in `tests/integration/protected-routing.test.ts:33-37`; it does not compose account provisioning, learner authentication, ready-media preparation and persisted attempt creation.
- **Trigger:** A regression at the identity-to-practice boundary, such as an incorrectly provisioned learner role/status or an authentication/route integration failure.
- **Consequence:** The Epic 5 acceptance journey can break between existing subsystem contracts without failing the new targeted tests.
- **Disposition:** Defer as tracked verification work. No runtime defect was observed in the independently exercised contracts, but the full first-practice composition remains unproven.
- **Prevention lesson:** Cross-epic composition stories need one happy-path browser or API journey spanning each newly joined boundary, not only unit tests of the reused capabilities.
