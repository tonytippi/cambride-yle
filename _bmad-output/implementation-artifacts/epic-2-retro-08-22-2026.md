## Findings

### Immutable provenance migration fails on migrated PostgreSQL

- **Source:** `db/migrations/0008_content_drafts.sql:34-38` binds both lifecycle and generic immutable-history triggers to `prevent_content_draft_history_mutation`; `db/migrations/0009_content_review_workflow.sql:5-10` replaces that function with a version that accesses `NEW.status`.
- **Trigger and consequence:** `content_generation_records` and `content_audit_events` have no `status` field. Their update/delete triggers fail with PostgreSQL `record "new" has no field "status"`, not the required immutable-history rejection. The current migrated-database test reproduces this at `tests/integration/migration-baseline.test.ts:342-344`; `npm test` failed with 1 failed and 210 passed tests.
- **Disposition:** Fix now. Split generic immutable-row protection from the content lifecycle transition function, rebind the two history tables, and preserve migrated-DB update and delete coverage.

### Published snapshot stores the wrong answer-policy shape

- **Source:** `src/features/content/infrastructure/repositories.ts:494-512` stores `policy[0]`, a `{ version, policy }` join wrapper, in `practice_set_items.answerPolicy`. `src/features/practice/infrastructure/repositories.ts:193-194` requires top-level policy fields such as `canonicalAnswer`, `inputKind`, and `normalisation`; `:225-226` returns `ITEM_INVALID` when this predicate fails.
- **Trigger and consequence:** A set published by Epic 2 cannot be submitted by the learner flow, because every persisted answer policy fails `isPolicy`. The snapshot must be a scoring-ready immutable policy, not a database query wrapper.
- **Disposition:** Fix now. Snapshot `policy[0].version` with any required stable policy identifier, then add a database-backed publish-start-submit regression test.

### Publication permits learner-unusable picture content

- **Source:** `src/features/content/application/content.ts:741-752` requires audio only for the two audio engines. `src/features/practice/infrastructure/repositories.ts:146-154` rejects `picture_true_false` and `picture_yes_no` without an image, and rejects `audio_picture_choice` without labelled images. `src/features/content/domain/contracts.ts:12` accepts only `altText`, while the learner runtime requires image `choiceLabel` for `audio_picture_choice` at `src/features/practice/infrastructure/repositories.ts:127-152`.
- **Trigger and consequence:** Published sets can contain picture engines without image media, and schema-valid audio-picture-choice media cannot carry the labels required by the player. Learners receive `ITEM_INVALID` after a set has passed publication.
- **Disposition:** Fix now. Define required media per engine in draft validation and set composition. Add a non-answer-revealing image `choiceLabel` contract for `audio_picture_choice`, require unique labels, and snapshot it.

### Validation does not enforce selected guidance task-template limits

- **Source:** `src/features/content/application/content.ts:321-436` validates controlled references and text safety but never reads or compares the selected guidance's `maxWords` or `maxOptions`. The generic draft schema permits up to ten options at `src/features/content/domain/contracts.ts:41`.
- **Trigger and consequence:** A question can exceed the selected guidance's task-format limits, complete review, approval, and publication without the required named validation finding. This conflicts with Epic 2.1 and 2.3 acceptance criteria in `_bmad-output/planning-artifacts/epics.md:115,141-143`.
- **Disposition:** Fix now. Load selected guidance in validation and return named `maxWords` and `maxOptions` findings; enforce the same rules before manual or generated draft persistence.

### Practice sets do not have the required independent lifecycle

- **Source:** `db/schema/content.ts:220-249` defines practice sets as only `published` or `retired`, and `src/features/content/application/content.ts:683-803` creates a learner-selectable published set directly.
- **Trigger and consequence:** A practice set cannot progress through the declared independent `draft -> in_review -> approved -> published -> retired` lifecycle before selection. Its composition has no standalone review/approval record, contradicting the Epic requirement at `_bmad-output/planning-artifacts/epics.md:153-156` and the technical decision at `_bmad-output/implementation-artifacts/epic-2-context.md:31-32`.
- **Disposition:** Fix now. Model the practice-set version lifecycle and audit-backed review/approval transition; only the published version should become learner-selectable.

### Readiness can prove the wrong topic and mislabels target coverage

- **Source:** `src/features/content/application/content.ts:137-168` groups readiness candidates by engine, paper, part, and guidance only; it reports `topicIds` but does not partition composition by them. The same block reports all primary/supporting targets as `vocabularyGrammarTargets` without their category.
- **Trigger and consequence:** Candidates from separate topics can combine to prove a set when neither topic independently has a viable 5-10 minute composition. Topic targets can also be displayed as vocabulary/grammar coverage. This violates the required per-topic/task-type proof and vocabulary/grammar distribution at `_bmad-output/planning-artifacts/epics.md:167-171`.
- **Disposition:** Fix now. Expand/group candidates by selected topic ID and task type, calculate composition per group, and load target category so vocabulary and grammar are reported separately.

### Verification misses the published-content-to-learner boundary

- **Source:** `tests/unit/content-application.test.ts:920-963` mocks publication and retirement persistence; the end-to-end suite seeds content directly rather than progressing it through staff authoring and publication. `tests/e2e/teacher-evidence.spec.ts:178-225` starts a seeded set but does not submit a staff-published one.
- **Trigger and consequence:** The answer-policy snapshot defect and learner-unusable media defects passed Epic 2 story tests because the staff-publish to learner-submit integration contract is not exercised.
- **Disposition:** Fix now. Add a database-backed integration or E2E path for controlled references, review/approval, media association, set publication, learner selection/start, submission, and retirement preserving open/completed attempts.

### Content feature aggregation is a maintainability risk

- **Source:** `src/features/content/application/content.ts:1-1062` combines draft generation, validation/review, lifecycle, publication, retirement, and readiness; `src/features/content/infrastructure/repositories.ts:1-563` additionally owns snapshot/tag derivation.
- **Trigger and consequence:** Cross-story invariants are difficult to reason about and isolate, as shown by publication and readiness defects crossing the same module boundaries.
- **Disposition:** Defer. After the blocking remediation, split application use cases into draft/generation, review lifecycle, publication, and readiness; keep repositories focused on database reads, locks, and writes.

## Acceptance Verdict

**Rejected.** Criteria are declared in `_bmad-output/planning-artifacts/epics.md:103-171`; all five stories are complete, but the Epic does not satisfy them. The migrated PostgreSQL test suite is failing, published snapshots do not meet the learner scoring contract, picture-engine publications can be learner-unusable, task-template limits are not enforced, practice-set lifecycle is incomplete, and readiness can return false-positive coverage. The eight remediation items above are proposed for the normal build workflow; none was applied by this retrospective.
