- (capability) CAP-1: Admin can create learner, teacher, and admin accounts, manage cohorts/enrolments, and revoke/delete accounts with diagnostic data when needed.
- (capability) CAP-2: Learner can sign in to a mobile-first PWA, see assigned practice, preload essential media, start or resume a draft, and preserve an in-progress response locally.
- (capability) CAP-3: Learner can complete the five P0 Starters task engines: picture true/false, picture yes/no, audio picture choice, audio name/number note-taking, and word-bank cloze.
- (capability) CAP-4: Learner can submit a complete practice set once and see answer review, approved explanations, and product-owned practice evidence only after submission.
- (capability) CAP-5: System deterministically scores item responses and stores immutable attempt evidence by paper, part, curriculum target, topic, answer policy, response, time, retry, and media playback.
- (capability) CAP-6: Teacher can view cohort and learner evidence, filter by required dimensions, resolve uncertain responses, identify gaps, and assign approved practice sets.
- (capability) CAP-7: Content editor can author original/licensed/generated drafts, validate curriculum/media/provenance, route review, preview mobile behavior, and publish or retire approved content.
- (capability) CAP-8: System can build an approved-only practice set and bind it to a learner or cohort while preserving immutable content snapshots for each attempt.
- (capability) CAP-9: Admin can run a supervised prospective-learner diagnostic by using the approved practice-set flow without public registration or a separate diagnostic template.
- (capability) CAP-10: PWA makes connectivity and media readiness clear, caches safe app/set assets, and recovers local drafts without caching answers, results, or teacher evidence.
- (constraint) All learner-facing content/media must be original, licensed, or approved generated material, use approved Starters curriculum tags, and never imply official Cambridge endorsement or results.
- (constraint) Feedback and correct answers are withheld until the learner submits the complete set; scoring is deterministic server-side and attempts use immutable published snapshots.
- (constraint) P0 is a responsive web/PWA modular monolith with server-side role/resource authorization, PostgreSQL system of record, private media storage, and local draft-only browser persistence.
- (constraint) Product reports use secure, building, needs practice, and not assessed yet; it must not present pass/fail, official scores, certificates, or Cambridge shields.
- (note) Companions preserve the assessment blueprint, UX DESIGN/EXPERIENCE contracts, and architecture spine; the brief is fully absorbed for traceability.
- (event) Spec self-validation pass 1: coherent; 10 capabilities contain intent and success, constraints and non-goals are explicit.
- (event) Spec self-validation pass 2: preserved brief requirements in kernel and retained detailed assessment, UX, and architecture contracts as adopted companions.
- (event) spec finalized
- (decision) P0 account removal is soft deactivation: revoke sessions and prevent future login while retaining practice/diagnostic records; automatic expiry and irreversible purge are deferred.
